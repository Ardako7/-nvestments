# Arda Research daily updates

The published Site exposes `GET /api/daily-bulletin` and `GET /api/update-info`.
Calling the bulletin reader refreshes its R2 cache once per Istanbul calendar day from the ten fixed official RSS sources in `web/official-rss-feeds.json`. It accepts no user-written content. POST/PUT and arbitrary content writes are rejected. An unsuccessful refresh retains the previous successful bulletin and marks it stale, with a one-hour retry cooldown. A successful result is also archived by calendar day. Verify persistence by making a second GET and comparing `updatedAt` and the `cached` flag.

The linked cloud task should retrieve the current Site URL using Sites, GET `/api/daily-bulletin`, then read it again to verify the result. No credentials or signed-in browser are needed for these public read operations. A stale result is a failed update, not a fresh bulletin. Report persistent source failure rather than saying that a refresh succeeded. Routine updates do not require a source commit or redeployment.

Current quote display uses the official TradingView embedding scripts and retains TradingView attribution. Quotes are provider-hosted and may be delayed. Neither the Site nor the cloud task may scrape widget prices or export the provider's data. Daily news refreshes do not change the dated technical reports, valuation scenarios, or ranking. Those retain their research cutoff until separately recalculated with an authorized analysis data source.

The public Worker explicitly serves only 104 HTML/CSS routes. Raw audit, company JSON, original OHLCV arrays and research input files are not public routes. Personal notes, theses, watchlists, saved screens and portfolios remain browser-local. Runtime source is generated by `scripts/build-live-public.py` from the verified research revision plus current feed and quote-display configuration; the Worker starter's build and artifact validation are used for publication.
